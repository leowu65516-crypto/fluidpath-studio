# FluidPath Studio · 元器件符号国际可识别性评估与优化方案

> 日期：2026-10-27 · 对照版本：v1.38.0（git `17a5d76`）
> 核心问题：各国技术人员在**不看名称**的前提下，能否一眼认出每个符号是什么阀 / 什么泵？
> 评估方法：把全部 58 种元器件符号实际渲染成对照表逐个视觉核验（临时脚本，用后即删）→ 对照 ISO 1219-1（流体动力符号）与 ISA-5.1（P&ID）惯例逐类判定 → 结合 63 节点整机图 27% 缩放的实机走查验证小尺寸可读性
> 用户背景：应用已交付 60+ 国经销商、韩国 / 阿联酋 / 台湾培训现场使用，"国际通用"不是加分项而是准入项

---

## 0. 直接回答

**不能。** 58 个符号里大约只有 **1/3** 能让不同国家的技术员在无名称辅助下稳定识别；**1/3 会猜或猜错**；**1/3 完全不可能猜出**（咖啡机品类专属件，任何标准里都没有）。而且最关键的问题不是"画得不好"——恰恰相反，多数符号作为**教学简笔画**是合格的——而是**画风体系与国际工程师的"母语"（ISO 1219）不同**。一个受过标准训练的德国 / 意大利液压工程师，看到 bowtie（蝶形）+ 顶部方框会读出"电磁阀"，看到双框并列才读出"三位阀"——当前三通阀的"圆圈 + P1/P3/P2"画法在他的词典里不存在。

分三档的详细判定见 §2，落地建议（含"先测后改"避免重工的验收协议）见 §3–§5。

## 1. 现状事实

- 符号实现：`src/symbols.tsx`（~1200 行），每个 NodeType 一个 `switch` 分支的手绘 SVG，**教学简笔画风**（圆角、拟物、彩色状态徽标"开/关/ON/OFF"内嵌）。
- 内嵌文字已做语言自适应：`symLang()` 按 html lang 切换（入/出 ↔ IN/OUT、开/关 ↔ ON/OFF），双语承诺在这部分已兑现。
- 图例（`legend.ts`）与悬停提示（名称+类型+状态）已存在——这是"看名称"的兜底，但用户问的恰是不看名称的第一眼。
- 优化方案文档（`FluidPath-优化方案.md` §3.3）早有"符号体系 2.0：教学简笔 / 工程示意双风格"的规划，**至今未实施**。

## 2. 逐类判定（58 个符号的三档分类）

### A 档 · 国际通用或强直觉（约 20 个，无需改）

| 符号 | 判定依据 |
|---|---|
| 截止阀 valve（蝶形 bowtie） | 与 ISO 1219 截止阀同形 |
| 单向阀 checkValve（三角+挡线+箭头） | ISO 惯例同构 |
| 球阀 ballValve（圆+手柄杆） | ISO 同形 |
| 安全阀 safetyValve（弹簧+斜箭头） | 接近 ISO 溢流/安全阀惯例 |
| 水泵 / 奶泵（圆形叶轮） | 接近 ISO 离心泵（圆+三角）的直觉变体 |
| 蒸汽锅炉（波浪蒸汽线） | 直觉清晰 |
| 换热器（矩形内锯齿） | 与 ISO 换热器惯例一致 |
| 过滤器（矩形内斜线） | 接近 ISO（ISO 用虚线，斜线是常见变体） |
| 三通 / Y 三通 / F 三通 / 十字 / 弯头 / 接头 | 管路件 universally 直觉 |
| 流量计（扇叶圆）、压力表（表盘指针） | 仪表 universally 直觉 |
| 进水口 / 出水口（箭头五边形 + IN/OUT） | 形状本身即方向语义 |

### B 档 · 会猜 / 会混淆（约 18 个，重点改）

| 符号对/符号 | 问题 |
|---|---|
| **safetyValve vs opv** | 两个都是"弹簧+三角+斜箭头"，仅 OPV 多一个 2px 红箭头——现场无法区分"超压泄放"与"OPV 泄压"两种职能 |
| **pressureGauge vs pressureSwitch** | 都是圆表盘+指针，压力开关的"电气触点"语义完全没表达（ISO 惯例：开关要带触点符号或方框） |
| **checkValve vs pressureRegulator** | 都是"阀 + 箭头"；小尺寸下"三角+挡线"与"蝶形+斜穿箭头"区分度不足，调压阀的"弹簧+箭头"ISO 语法缺失 |
| **coffeeOutlet / milkOutlet / hotWaterOutlet / groupHead（4 件 6 形）** | **同一个水槽形轮廓，只靠 3px 的液滴颜色区分**（咖啡棕/奶白/热水黄）——实机 27% 缩放下色点是亚像素，等于四件同形。这是全表最严重的识别问题 |
| **hotWaterWand vs steamWand** | 两个竖杆几乎同形，只靠杆尖微差 |
| **solenoid3 三通电磁阀** | "圆圈端口 + P1/P3/P2 + 绿色激活线"：教学上直白，但 ISO 用户期待"双框并列 + 双箭头"（两位三通）画法——受过训的工程师会迟疑 |
| **diaphragmValve2 / diaphragmValve3** | ISO 隔膜阀是"拱顶 dome"形；当前画的是"圆角执行器帽 + 蝶形"，隔膜语义没表达；三口切换阀用"圆 + P1P2P3"更像接线端子排 |
| **solenoid2 vs pulseAirValve vs diaphragmValve2** | 三个"蝶形 + 顶部执行器帽"，执行器帽内的差异（线圈线/斜线）在库面板尺寸下不可辨 |
| inlet vs outlet（仅形状语义时） | 箭头方向对，但两件形状同构，翻转图或旋转后会误读 |

### C 档 · 品类专属，任何国家标准都没有（约 12 个，只能靠"约定 + 图例"）

冲泡缸 brewChamber、即热加热块 thermoblock、粉料搅拌器 powderMixer、糖浆瓶 syrupBottle、储液罐（圆角矩形+液面线）、热水锅炉（矩形+咖啡豆图标）、外置压力罐（囊袋线）、脉冲空气阀、传感器 sensor（菱形）、NTC 探针、普通/金属接头（圆角矩形块）、自定义图形。

**这一档的正确策略不是"改成标准"（标准里不存在），而是：① 保证品类内互不混淆；② 全部进图例；③ 形状语义对非中文用户直觉可读**（如 thermoblock 的加热波浪线已是好的范例）。

## 3. 根因与战略判断

1. **画风定位没错，深度不够**。教学简笔风的"低门槛"主张对培训学员成立；但交付对象里还有另一群人——**厂商研发、海外经销商技术员**——他们的符号母语是 ISO 1219。两群人需要的是**同一数据、两套皮肤**，不是二选一。这正好是内部优化方案"符号体系 2.0"双风格的原始动机，至今未做。
2. **"品类专属件"是护城河也是雷区**。咖啡豆锅炉、冲泡缸这些符号让产品亲切；但 B 档里那些"半标准件"（阀类）是真正international 误读的来源——它们恰恰是排障教学的主角。
3. **色点是当前最脆弱的差异通道**。色弱用户 + 打印黑白 + 27% 缩放三个场景同时失效。形状必须先于颜色承担区分职责。
4. **先测后改，避免重工**。符号重画 58 个是大工程；而真正必须动的只有 B 档约 18 个。用一次跨国识别率测试锁定低分清单，改造范围立刻从 58 缩到 10–18。

## 4. 优化方案（按优先级）

### P0 · B 档止血（形状差异止血，不动架构，2–3 天）

| # | 改动 | 说明 |
|---|---|---|
| 1 | **出口件形状分化**：咖啡出口=带杯沿缺口、牛奶出口=奶滴浮标、热水出口=波纹横线、冲煮头=带分流器双槽——用形状替代 3px 色点做第一区分，颜色降为辅助 |
| 2 | **safetyValve vs OPV 标准化区分**：安全阀保留"弹簧+斜箭头"（ISO 溢流阀惯例）；OPV 去掉弹簧改"纯泄放箭头+小方框"（ISO 减压/泄放另一分支），两件一眼可分 |
| 3 | **pressureSwitch 加电气触点**：表盘旁加斜线触点符号（ISA-5.1 惯例），与纯仪表 pressureGauge 拉开 |
| 4 | **pressureRegulator 补 ISO 语法**：蝶形+穿阀箭头+弹簧（ISO 调压阀三要素），与单向阀的"三角+挡线"彻底分离 |
| 5 | **hotWaterWand / steamWand**：蒸汽杆加"出汽三横线"，热水杆加"水滴"，杆身形状区分 |
| 6 | **三通阀加 A/B 端口刻字**（ISO-lite）：激活支路刻"A/B"字母（现有画布徽标已有，刻进符号本体，静态可读） |

### P1 · 双风格符号体系（ISO-lite 皮肤，1–2 周）

`NodeSymbol` 加 `style?: "sketch" | "iso"` 参数（settings 全局切换，默认 sketch）：

- **iso 风格规则**：正交线条、无圆角拟物、无咖啡豆等拟物元素；阀=蝶形+标准执行器符号（方框=电磁、拱顶=隔膜、斜箭头=泄放）；三通=双框并列双箭头；泵=圆+三角（ISO 定量泵惯例）；仪表=圆圈+ISA 字母标签（PI/PS/FT）。
- **品类专属件在 iso 风格下用"ISO 语法 + 简单几何"重述**：冲泡缸=矩形+上下箭头对（进/出），thermoblock=矩形+加热波浪线（已是 ISO 加热惯例）。
- 切换入口放在显示设置，导出 PNG/PDF 跟随当前风格——**给海外经销商的图纸用 iso，给新学员的课件用 sketch**。
- 架构可行性已核实：symbols.tsx 是逐 type 的纯函数 switch，加参数分支即可；NODE_DEFS 数据（端口/尺寸）两风格共用，引擎零改动。

### P2 · 跨国识别率测试协议（先于 P1 全面铺开，半天准备）

1. 从 58 符号中抽 **20 个**（B 档全部 + A/C 档各抽代表），生成无文字对照表。
2. 请 3 国 × 5 名技术员（韩国 / 阿联酋 / 台湾——现有培训关系可直接覆盖）每符 10 秒写"这是什么"。
3. 统计识别率：**<60% 的符号进 P1 必改清单；60–80% 的进 P0 微调；>80% 的不动**。
4. 测试在 P0 改动前后各跑一轮——P0 六项改动的效果也用同一协议验收，避免"设计师觉得好"而"用户认不出"的单向判断。
5. 成本：一次线上会议即可完成（屏共享 + 表单），无需出差。

### P3 · 兜底与配套（半天）

- 图例增强：导出物强制可选手动图例区（现有 legend 扩展），海外交付 PDF 默认带上。
- 悬停提示已有，补一项：按住 **?** 键在画布上悬停显示符号名浮签（演示/验收模式下讲师快速解释用）。
- 术语表（i18n glossary）：符号名中英之外补韩/阿语关键词列（覆盖现有两大培训市场），进 HelpPanel。


## 6. 排期与验收基线

| 批次 | 内容 | 量级 | 验收 |
|---|---|---|---|
| 第 0 批 | 跨国识别率测试（基线轮） | 0.5 天 | 20 符号 × 15 人识别率数据入库 |
| 第 1 批 | B 档止血六项 | 2–3 天 | 复测 B 档符号识别率 ≥80% |
| 第 2 批 | ISO-lite 双风格 | 1–2 周 | 同一图纸双风格交付样张；风格切换零回归 |
| 第 3 批 | 图例/快捷浮签/多语术语 | 0.5 天 | 海外交付 PDF 默认带图例 |

**对"避免重工"的兑现**：先测后改把重画范围从 58 缩到实测低分符号；双风格复用同一 NODE_DEFS 数据与引擎，草图/工程两套皮肤一次数据投入；品类专属件不改标准改"约定+图例"，避免不存在的标准带来的无穷打磨。
