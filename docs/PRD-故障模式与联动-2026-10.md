## 1. 问题证据（v1.46.0 实测）

在本地构建（`npm run build` + `vite preview`，浏览器 1324×963 / 900×700）实测了四条用户旅程：

| # | 旅程 | 实际发生 | 卡点 |
|---|---|---|---|
| J1 | 新建空图纸 → 进入故障模式 | 右侧面板出现「故障知识库」空态（导入/示例）、新建代码表单；画布为空白网格。编辑模式的三步起步卡在故障模式**不显示** | 没有任何"你还需要一张图纸"的提示；不知道先做什么 |
| J2 | 有图纸（BCMTS）+ 无故障库 | 面板只有新建代码表单；创建代码后，需要自己发现「关联水路 → 替换为当前选择」才会高亮 | 无引导、无步骤感；"关联水路"与后来的"部件组绑定"是两套概念 |
| J3 | 有图纸 + 导入 MILK-KB（23 组未绑定） | 咨询台正常（9 症状/52 原因）；但勾选 E037/E038 两个代码后**画布零高亮**（代码的排查范围引用的是未绑定的部件组） | 用户以为"叠加查看"或"故障码"坏了 |
| J4 | 空图纸 + 导入 MILK-KB | 23 组未绑定；「定位部件」「替换/追加/移除绑定」「采用名称建议」全部不可用（没有画布对象可绑/可建议） | 死路：没有任何出口提示（去打开图纸 / 去智能绘图生成） |

另有三个交互事实：

| # | 事实 | 证据 |
|---|---|---|
| J5 | 「叠加查看」只是把多个代码的绑定范围取并集画出来，没有图例、没有共同部件/差异汇总、没有目的说明；在 J3 未绑定场景下等于完全无效果 | 勾选 E037+E038 后 `svg [data-fault-code]` 有 2 组，但可见轮廓 0；面板仅一句 "Select multiple codes to view them together." |
| J6 | 「模拟此代码」只把代码加入 `injectedIds` → 画布高亮该代码的排查范围（教学注入），**不改泵阀状态、不触发停流传播**，看不到"这个故障会让机器怎样" | [session.ts](../src/fault-codes/session.ts) `toggleInjectedFault`；engine 只读 `Node.fault`/`Pipe.fault` |
| J7 | 部件组绑定入口藏在咨询台折叠区与详情卡里；没有画布侧引导（要框选？多选怎么选？选完点哪个按钮？）；绑定成功只有数字变化 | [KbConsultPanel.tsx](../src/components/KbConsultPanel.tsx) |

### 根因（三条）

- **R1 没有"当前在哪一步"的状态模型**：图纸 / 故障库 / 落点 / 演练四个前置条件中缺哪个、缺了该干嘛，界面不表达。
- **R2 故障码与机器状态/工况没有链接**：知识库只有"查/看"，没有"演"；`Node.fault`、工况快照、引擎停流传播这些能力已经存在，但没有接到故障码上。
- **R3 绑定被当成用户任务而不是元数据操作**：23 个部件组要手工绑定，没有向导、没有自动映射、没有即时反馈闭环；且"代码排查范围"与"知识库部件组"两套绑定并存，概念重复。

## 2. 目标与非目标

### 目标（可验收）

1. 任意前置状态下进入故障模式，**30 秒内知道下一步**（起步卡 + 四步进度条）。
2. 从"选中一个故障码"到"看到水路现象"**一次点击**：应用基线工况 → 注入故障 → 引擎重算 → 差异高亮 → 步骤说明 → 一键还原。
3. 23 个部件组的绑定从手工作业降为"建议 + 确认"或一次画布向导完成；任何时刻 Esc 可退出、可撤销、可"稍后再绑"。
4. 「叠加查看」要么有明确目的（多报警共因分析：图例 + 交集部件），要么移除，不再保留"无解释的并集高亮"。

### 非目标（保持不做）

- CFD/精确求解、真机读数、IoT 三数据联判、盲测/考场计分。
- 不改引擎判定语义：演练只是**注入工程状态**（复用 `Node.fault`/`Pipe.fault`/工况快照），视觉差异来自既有引擎输出。
- 不把演练结果写入工程导出；演练 overlay 与教学覆盖一样只属于显示层。

## 3. 前置状态机与起步卡（P0）

进入故障模式时计算前置状态：

```text
S0 无图纸      : diagram.nodes.length === 0
S1 有图无库    : 无 diagnostics 且无 symptoms（0.1/0.2 空 profile）
S2 有库未落点  : 存在未绑定部件组，或存在代码的排查范围为空
S3 就绪        : ≥1 个代码有可解析的排查范围
```

顶部「故障工作台」向导条常驻（可折叠）：`① 图纸 → ② 故障库 → ③ 落点 → ④ 演练`，每步显示完成/未完成，点击跳到对应动作。

### 起步卡（首次进入自动展开，关闭后可通过向导条重开）

| 状态 | 标题 | 动作（按钮 + 预期结果） |
|---|---|---|
| S0 | 故障模式需要一张图纸才能定位水路 | ① 打开图纸 JSON ② 用「智能绘图」生成一台机器 ③ 载入示例（BCMTS + 示例知识库，一键进入 S3 演示） |
| S1 | 还没有故障知识库 | ① 导入 `.fluidkb.json` ② 加载示例知识库（奶泵 V7） ③ 手工新建第一个代码（3 步微型引导：编码名 → 绑定范围 → 加排查步骤） |
| S2 | 知识库已就绪，还需把部件组落到画布 | ① 开始绑定向导（见 §5） ② 采用名称建议 ③ 先浏览咨询台，稍后再绑 |
| S3 | 可以开始演练 | ① 选择故障码开始演练（见 §4） ② 查看"多码对比"说明 ③ 重看 3 分钟示例 |

通用入口：任何状态都提供 **「3 分钟示例演练」**（J1–J3 都不需要用户准备数据）。

### 组件级细则

- 所有禁用按钮必须给原因（`title` + 行内提示）：如"未绑定排查范围，画布不会高亮 → 去绑定"。
- 空态/缺失态一律给"下一步"，不允许只有一句解释。
- 状态变化时向导条即时更新（绑定完成、导入完成、代码范围清空）。

## 4. 故障演练：把故障码接到水路与工况上（P1 核心）

### 4.1 数据模型（profile 0.4-draft，全部可选，0.1–0.3 只读兼容）

```ts
/** 故障演练：一个故障码"演出来"需要的最小状态与提示。 */
interface FaultDrill {
  /** 基线工况名（引用 settings.workConditions；工况快照已含 pump/valve/fault/disabled/介质/显示）。 */
  conditionName?: string;
  /** 在基线工况之上叠加的最小覆盖（优先于工况）。 */
  overrides?: {
    nodes?: { nodeId: string; fault?: NodeFault | null; pumpOn?: boolean; valveState?: "open" | "closed"; valvePath?: "A" | "B" | "off"; disabled?: boolean }[];
    pipes?: { pipeId: string; fault?: "pipeBlocked" | null }[];
  };
  /** 教学断言（只用于"预期现象"提示，不参与引擎判定）。 */
  expected?: {
    stoppedPipes?: string[];
    flowingPipes?: string[];
    abnormalNodes?: { nodeId: string; label: LocalizedText }[];
  };
  /** 画布追加标注（overlay 渲染，不进工程导出/图纸 JSON）。 */
  annotations?: { targetId: string; text: LocalizedText }[];
  /** 演练结束恢复到的工况名；缺省则恢复进入演练前的实时状态。 */
  restoreCondition?: string;
}
// FaultCode 增加：drill?: FaultDrill
```

理由：`WorkCondition.componentProperties` 已经包含 `fault/disabled/valveState/valvePath/pumpOn`（见 [presets.ts](../src/presets.ts) `NODE_PROPERTY_KEYS`），所以"故障工况"不需要新造状态容器，`conditionName` + 少量 `overrides` 即可；引擎与导出链路零改动。

### 4.2 演练交互

按钮语义拆两档（替代现在含糊的「模拟此代码」）：

1. **只看范围**（保留现状）：高亮排查范围，不改状态。
2. **演练故障**（新，默认主按钮）：
   1. 记录当前实时状态（可撤销）→ 应用 `conditionName`（若有）→ 叠加 `overrides`；
   2. 引擎自动重算（现有 `updateDiagram` 管线）；
   3. 画布进入「演练对比」overlay（见 §4.3）；
   4. 右侧演练卡：故障码、工况名、"N 处变化"、预期现象 vs 实际、排查步骤（逐条"聚焦"、可勾完成）、结论/处置（复用 causes 的 why/act）；
   5. 顶部条常驻：`⚠ 演练中 · E045 · 蒸汽支路停流` + 「还原」按钮（Esc 也可还原）。
   6. 还原：恢复进入前状态（一次 undo 等价的显式还原），退出演练 overlay。

### 4.3 差异视觉（沿用现有 overlay 通道，只读）

| 变化 | 画法 |
|---|---|
| 新停流管（演练前流、演练后停） | 红色虚线 + 停流动画 + 小角标「故障致停」 |
| 新流动管（演练前停、演练后流） | 绿色虚线 + 方向箭头 |
| 受影响元件 | 元件右下角徽标：⛔停泵 / 🔒卡关 / 🔓卡开 / 🚫禁用 |
| 追加标注 | 编号 ① ② ③ 的引线卡（复用 annotation 视觉语言，overlay 绘制） |
| 排查范围 / 部件组 | 沿用故障码高亮与概率分档，演练时降低透明度避免抢戏 |
| 图例 | 画布左下角一行：新停流 / 新流动 / 注入 / 标注 |

数据来源：进入演练时对 `snapshotPipeStates(diagram)` 做前后 diff（`presets.ts` 已有 `diffStateIds`），零新引擎逻辑。

### 4.4 示例 drill（随示例 KB 提供 3–5 条）

- E041 牛奶清洗电磁阀（卡关）→ 清洗支路停流、奶路仍可出奶；
- E045 奶泵故障（泵卡死 / 停转）→ 奶路全链停流、蒸汽支路不受影响；
- E037 奶泵不在位 → 模拟 pump 禁用/未装；
- E048 排废三通阀 → 排废支路停流、咖啡主路正常；
- 每条含 2–3 条 annotation + expected 列表，作为教学样例与录入模板。

## 5. 绑定体验重做（P0）

### 5.1 概念统一

- 只保留一套语言：**部件组 ↔ 画布对象**。
- 故障码的「排查范围」改为引用部件组（`highlightBindings` 已引用 groupId，语义不变）；UI 删除"关联水路/替换为当前选择"这套独立绑定入口，统一为"绑定范围"。
- 旧数据迁移：0.3 及以前的代码自带 `circuit-*` 组，自动转换为"代码范围部件组"并在 UI 中标记为"该代码范围"；用户可按需合并到知识库部件组。

### 5.2 三种绑定方式

1. **建议 + 确认**（已有，增强覆盖率）
   - 词典：部件名核心 ↔ `node.label` / `pipe.label`（已有）+ `node.type` 词典（奶泵→milkPump、NTC→探头类、锅炉→steamBoiler/hotWaterBoiler）+ 常见别名（奶管→管路类节点）。
   - 显示"建议 N 项（预览高亮）"，点「采用建议」才写入；多个候选时列出候选清单让用户勾选。
2. **画布点选向导**
   - 进入"绑定模式"：左侧浮层显示 `当前组 3/23 + 组名`、提示"在画布点选元件/管路，可多选；Enter 确认，S 跳过，Esc 退出"。
   - 点选时目标高亮，确认后该组绑定并闪光 200ms，自动进入下一组；顶部进度条与"稍后再绑"入口。
   - 支持从右侧组列表反向"定位到画布"。
3. **反查绑定**
   - 画布选中对象后，面板列出"这些对象可以属于哪些部件组"（候选按名称/类型匹配度排序），一键挂接。

### 5.3 反馈与出口

- 绑定成功：画布立即按该组描边 200ms 闪光；进度 `3/23`。
- 完成时：`全部落点完成 → 开始演练` CTA。
- 代码卡片显示绑定状态：`范围未绑定（画布不会高亮）→ 去绑定`。
- 任意时刻可退出向导，未完成进度保留（本次会话）。

## 6. 叠加查看 → 「多码对比」（P1）

现状无解释的并集高亮改为有目的的比较模式：

- 进入条件：勾选 ≥2 个故障码；面板标题改为「多码对比」并给一句目的说明："多个报警同时出现时，交集部件是共同原因候选"。
- 图例：每个代码一种描边色（取 presentation.color），列出代码 + 范围对象数。
- 汇总卡：**共享部件（交集）** 列表（点击定位）；各自独有范围可折叠。
- 若交集为空：明确显示"这些代码没有共同的排查对象"，避免用户误以为没生效。
- 成本取舍：若 P1 排期紧，先做图例 + 交集列表（半天），完整对比视图放 P2。

## 9. 验收标准

1. **状态机**：S0–S3 各自进入故障模式，起步卡动作可达成下一状态；无空白禁用按钮（有原因与跳转）。
2. **学习成本**：首次用户（无提示）从进入故障模式到点出第一次「演练」< 30 秒（可用 3 分钟示例验证）。
3. **绑定**：23 组可在向导内完成；Esc 退出后进度不丢；任一步可撤销；绑定后画布 200ms 内出现该组描边。
4. **演练**：注入/还原各一次 undo 可回到演练前；差异集合与引擎 `computeDisabledPipes` 输出一致（固定图纸 + 合成 drill 的纯函数回归）；导出 JSON/PNG/SVG 不含演练 overlay。
5. **对比**：≥2 码显示图例、交集列表；无交集有明确提示；未绑定代码不再出现"勾选后画布无变化且无说明"。
6. **兼容**：0.1–0.3 图纸打开行为不变；0.4 KB 在旧版本的拒绝提示可读（升级提示）。
7. **回归**：前置状态机、drill 解析、diff 选择、建议映射均为纯函数并配单测；现有 604 用例保持绿。

## 10. 风险与决策点（需拍板）

1. **0.4 版本门控**：旧版应用会拒绝 0.4 KB。策略二选一：A) 发布 0.4 前强制升级提示；B) 把 drill 作为 0.3 的可选扩展字段（需放宽 0.3 白名单，旧版仍会拒绝未知字段——本质相同）。建议 A，并在 0.4 中保留导出降级（丢 drill、保留 0.3 定义）。
2. **演练修改工程状态的边界**：演练=真实工程状态注入（可撤销、退出还原），与 `teachingOverride`（只改显示）严格区分；UI 必须常驻"演练中"标识，防止误把演练状态当成图纸状态保存。
3. **自动映射宁可少绑不可错绑**：所有自动建议必须人工确认；建议覆盖率目标 ≥50%（当前奶泵 KB ↔ BCMTS 实测仅奶泵等少数可匹配）。
4. **多码对比是否保留**：若评估认为使用频率低，可只做图例 + 交集列表（P1 半天）并观察。
5. **示例数据策略**：示例 KB（MILK-KB）为奶泵模组，但示例图纸 BCMTS 是整机——部分部件组在本图中不存在属于正常现象；示例演练应挑选能落到本图的码（如 E041/E045），避免"建议不到 = 功能坏了"的错觉。
