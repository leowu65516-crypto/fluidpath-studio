# 智能绘图 PRD（v0.1）

> 版本：2026-10-25  
> 状态：P0+P1 已在 1.32.0 落地，待可用性测试。  
> 基于代码：FluidPath Studio 1.31.5  
> 范围：模板生成 + 引导完善 + 保存/离开提醒  
> 明确不做：应用内 LLM、任意自然语言生成任意拓扑、自动布线避障、静态图片生成

---

## 1. 背景与问题

### 1.1 当前状态

1.31.5 已把原本无人引用的 `AiDrawingPanel` 接回应用：工具栏有「AI 绘图」，右栏能打开面板。但面板仍然是**协议调试器**，不是新手工具：

- 「下载 AI 上下文」给出一个包含协议版本、SHA-256、组件目录、整张图纸的 JSON。
- 「载入示例指令」给出一段 JSON，不是一张图。
- 「指令 JSON / 校验并预览」要求用户自己写出符合 `fluidpath.ai-operations 0.2-draft` 的 5 类操作。
- 新手不知道“上下文”是什么、该把文件交给谁、AI 返回什么、下一步做什么。

这不是文案问题，是**缺少从“我想画什么”到“一张可编辑的图”的产品路径**。

### 1.2 保存心智同样断裂

当前状态栏只有两种状态：

```text
● 未保存        /        ✓ 已保存
```

但实际存在三种完全不同的“保存”：

| 行为 | 现状 | 用户理解 |
|---|---|---|
| 自动保存到浏览器 | 编辑后 800ms 防抖写入 localStorage，保留 5 个版本 | 看不到，以为没保存 |
| 保存为 JSON 文件 | 工具栏「保存」/「保存到本地」 | 以为这才是保存 |
| 导出 PNG/PDF/GIF | 导出面板 | 以为导出图片就等于保存了图纸 |

用户改完图，状态栏仍显示「未保存」，即使自动备份已经写好；关闭时又弹「是否另存图纸到本地？」。两套语义互相冲突，新手很容易误判“我的图是不是丢了”。

### 1.3 产品机会

把「AI 绘图」改名为「智能绘图」，默认只做两层：

1. **模板生成**：用场景卡 + 少量选项，生成一张可编辑的起步图。
2. **引导完善**：生成后告诉用户“还缺什么”，用功能块和接点引导继续画。

同时建立一套**保存信心系统**：任何编辑/引导操作后，用户都能明确知道“已自动保存在本机”“还没有保存成文件”“离开会怎样”。

## 2. 目标与非目标

### 2.1 目标

1. 新手从空白画布到一张结构检查通过的咖啡/奶路图，**≤3 次点击、≤2 分钟**，全程不出现 JSON/协议术语。
2. 生成结果必须是**可编辑的 FluidPath 图纸**，不是静态图片；插入后可以改阀、跑工况、导出。
3. 任何编辑或引导操作后，用户能回答三个问题：
   - 我的修改现在保存在哪里？
   - 要分享/换电脑，需要做什么？
   - 直接关掉会丢吗？
4. 引导要“教方法”，不是替用户画完：每插入一个块，解释它包含什么、下一步接哪里。

### 2.2 非目标（本版不做）

- 不接应用内模型，不做“任意一句话生成任意拓扑”。
- 不把现有协议面板作为默认入口；它保留在「高级」中，本版不投入。
- 不做自动布线避障；模板用固定网格布局，允许用户手动调整。
- 不做静态文生图（PNG/海报）；导出只是图纸的附属能力。
- 不做完整 tag 体系；本版只做线路编号重复检查与重排。

## 3. 用户画像与场景

### 3.1 主画像：咖啡机培训师 / 销售 / 售后

- 懂咖啡机的水路、奶路、蒸汽、清洗，但不一定懂绘图工具。
- 打开 FluidPath 的目的：快速做一张能讲解、能发给他人的液路图。
- 对“协议、哈希、JSON、requestId”没有背景，也不应该被要求理解。
- 最怕两件事：画不出来、改完丢了。

### 3.2 三个核心场景

**场景 A：第一次打开，想画一张咖啡机水路**

- 看到空白画布，不知道从哪个元件开始。
- 期望：“我说一下机型/功能，你给我一张能改的草图。”

**场景 B：已有一张图，想加一段奶路**

- 不想从零拖 6 个元件、连 7 根管。
- 期望：“加一个奶路块，告诉我接哪里。”

**场景 C：改完准备发给同事/客户**

- 不知道自动保存和保存文件的区别。
- 期望：“告诉我现在存哪了，怎么发给别人，关掉会不会丢。”

## 4. 竞品与参考拆解

| 产品 | 观察到的做法 | 可借鉴 | 不照搬 |
|---|---|---|---|
| **Excalidraw** | 本地优先：自动保存到浏览器；同时提供显式 `.excalidraw` JSON 导出；界面极简 | 自动保存与文件导出分开表达；JSON 是“交付物” | 不学它的空白画布冷启动，对新手太自由 |
| **tldraw** | `persistenceKey` 自动写入 IndexedDB、跨标签同步；快照用于服务端；提供 Starter Kits | 本地自动保存要做到无感；模板/Starter Kit 降低空白焦虑 | 不引入协作/服务端同步 |
| **Eraser DiagramGPT** | 按图类型给提示词（流程图/架构/ERD/时序…）→ 生成 → “Save and Edit Diagram” 继续编辑 | 先选图类型再描述；生成结果必须可编辑；提示词要具体 | 不让用户写自由长 prompt；不做多图类型 |
| **Figma / Canva / Miro** | 首次进入以模板中心/“What will you design?”起步；保存状态持续可见；版本历史 | 模板卡 + 持续保存状态 + 版本历史兜底 | 不做账号/云协作 |
| **draw.io** | 新建时先选模板分类或空白图；桌面端有未保存离开确认 | “新建即选模板”的入口顺序 | 不学复杂的模板分类树 |
| **Appcues / Userpilot 等 onboarding 模式** | 3 步清单、coach mark、按需提示、可跳过 | 只教 3 件事；在动作发生处提示；不堆弹窗 | 不做多页产品导览 |

- tldraw Starter Kits（模板/起步套件）：https://tldraw.dev/starter-kits/overview

### 4.1 提炼出的四条原则

1. **自动保存要无感，文件保存要显式**：两者不能共用“已保存”三个字。
2. **模板先于画布**：新手需要“可修改的起点”，不是无限空白。
3. **先选场景，再描述**：自由 prompt 对新手太难；选项 + 模板卡更可靠。
4. **提示发生在动作处**：插入后提示保存、连接时提示接点、离开时提示后果；不要开场讲十分钟。

## 5. 产品原则

1. **结果命名**：入口叫「智能绘图」，副标题“描述或选择模板，快速得到可编辑液路图”；不叫“AI 绘图”，不出现协议词。
2. **渐进披露**：默认只看到模板卡和 2–3 个选项；高级 JSON 收进「高级」。
3. **一次一个主行动**：向导每步只有一个主按钮；保存提示只有一个主行动“保存文件”。
4. **可撤销的生成**：插入/追加都是一次撤销步骤；失败不破坏原图。
5. **教方法，不替用户做完**：每个块都说明“包含什么、下一步接哪里”。
6. **不打扰**：保存提示按里程碑出现，不在拖动/输入时弹窗；可关闭且记住。

## 6. 信息架构与入口

### 6.1 入口

| 位置 | 现状 | 改为 |
|---|---|---|
| 工具栏 | 「AI 绘图」 | 「智能绘图」✨，放在「回路诊断」旁边 |
| 空白画布 | 「插入循环回路模板」「打开 JSON」 | 主 CTA「✨ 智能绘图」；次级「打开已有图纸」「从空白开始」 |
| 生成后 | 无 | 右栏「继续完善」面板 |
| 高级 | 当前协议面板 | 折叠在智能绘图面板底部「高级：结构化指令」；本版不推广 |

### 6.2 形态

- **生成阶段用居中 Modal**：宽 880px，三步，模板卡有足够空间展示缩略图。右栏 300px 太窄，不适合做新手向导。
- **完善阶段用右栏 Panel**：插入完成后关闭 Modal，右栏显示「继续完善」；不打断画布操作。
- 两者共享同一套模板/预览数据。

## 7. 核心用户旅程

### 7.1 旅程 A：第一次生成

```text
空白画布
 → 点「智能绘图」
 → Step 1 选场景（基础水路 / 咖啡冲泡 / 奶路 / 整机）
 → Step 2 选配置（奶泵 / 蒸汽 / 清洗旁通 / 双奶罐）
 → Step 3 预览 + 结构摘要
 → 「插入画布」
 → 画布高亮新增元件 + 适应视图
 → 右栏「继续完善」+ 一次性保存提示
```

关键体验：

- 每一步都能“上一步”，不丢选择。
- 预览是真实 SVG（复用画布符号），不是占位图。
- 插入后 1.5 秒内不弹任何 modal；先让用户看到图，再提示保存。

### 7.2 旅程 B：已有图，加一段奶路

```text
右栏「继续完善」
 → 点「+ 加一段奶路」
 → 弹出小预览：奶罐→选择阀→奶泵→奶出口
 → 画布高亮可用接点（如“热水锅炉出水”“咖啡出口前”）
 → 点选接点
 → 自动放置到右侧并连接入口
 → 未接出口显示「待连接」徽标
 → Toast：已插入 4 个元件；本机已自动保存 [保存文件] [继续完善]
```

如果用户不想现在连接：

- 提供「先放到右边，我自己连」；插入后所有开口端口显示橙色「待连接」。
- 右栏「检查图纸」列出待连接数量，点击可定位。

### 7.3 旅程 C：改完保存/离开

```text
编辑/生成/加块
 → 状态栏显示「本机草稿 14:32 · 文件未保存」
 → 首次编辑后出现一次保存教练卡
 → 用户点「保存文件」→ 选择路径 → 成功 Toast + 状态变为「已保存到 xxx.json」
 → 或点「以后再说」→ 不再弹卡，状态栏持续提示
 → 关闭窗口：保存并退出 / 不保存 / 取消
```

## 8. 功能需求

### F1 模板生成向导（P0）

**F1.1 场景卡**

| 模板 | 说明 | 默认选项 |
|---|---|---|
| 基础水路 | 进水口 → 水泵 → 热水锅炉 → 出口 | 单锅炉、无奶路 |
| 咖啡冲泡 | 水路 → 锅炉 → 冲泡阀 → 冲泡缸 → 咖啡出口 + 排废 | 含排废 |
| 奶路 | 奶罐 → 选择阀 → 奶泵 → 加热/混合 → 牛奶出口 | 单奶罐、含加热三通 |
| 双锅炉整机 | 水路 + 咖啡 + 蒸汽 + 奶路 + 清洗旁通 | 全选 |

每张卡包含：

- 16:9 SVG 缩略预览（用真实节点符号）
- 标题（16px）
- 一句话说明（12px）
- 标签：`约 8 元件` `约 7 管路`
- 选中态：2px 主色边框 + 浅色底

**F1.2 配置选项**

- 奶路：单奶罐 / 双奶罐（选择阀 A/B）
- 蒸汽：无 / 蒸汽锅炉 + 蒸汽杆
- 清洗：无 / 清洗旁通（清洗三通阀 + 排废）
- 出口：咖啡出口单/双、牛奶出口单/双、热水出口
- 选项最多 4 组；默认给推荐值；右侧实时显示“约 N 元件 / N 管路”。

**F1.3 预览与插入**

- 预览区域自适应缩放，保留 32px padding。
- 摘要行：`18 个元件 · 17 段管路 · 2 处待连接`。
- 主按钮「插入画布」；次按钮「上一步」「换一个模板」。
- 空画布：直接加载，替换空白。
- 非空画布：显示选择「追加到当前画布右侧（推荐）」/「新建一张图」；追加是一次撤销。
- 插入后：选中新增元件、适应视图、显示 600ms 高亮；右栏切到「继续完善」。

**F1.4 结构自检**

生成后立即跑 `collectAdvice(diagram)`：

- 0 个结构 error 才允许“完成”；
- 有 warning 时在预览页显示「检查到 2 处可改进」，可展开查看；
- 有 error 时显示「生成结果有 1 处需要处理」，提供“返回修改选项”或“仍然插入（可稍后修复）”。不静默插入坏图。

### F2 引导完善（P0/P1）

**F2.1 右栏「继续完善」**

插入后右栏固定显示：

```text
这张图已经可以用了
[✓] 已生成 18 个元件
[!] 2 处待连接
[!] 1 组管路编号重复

下一步可以加：
[+ 奶路] [+ 蒸汽] [+ 清洗旁通] [+ 排废]

[检查图纸]  [保存文件]
```

- 「待连接」点击后定位并高亮开口端口。
- 「检查图纸」调用 `collectAdvice`，只显示结构问题；一键修复沿用现有 `applyFix`。
- 每个加块卡片有 1 行说明：“奶路：奶罐→选择阀→奶泵→奶出口”。

**F2.2 接点引导**

点击加块后：

1. 弹出 320px 小预览，显示块内元件和入口/出口。
2. 画布高亮 2–4 个兼容接点，标签写成“接这里：热水锅炉出水”，不是端口 ID。
3. 用户点选接点 → 自动放置并连接；未接端口标记「待连接」。
4. 用户点「先放右边」→ 只放置不连接，右栏提示“还有 2 个口没接”。

兼容性判断复用 `validatePipeConnection` / 端口方向 / 介质规则；不兼容的端口变暗。

**F2.3 关键词输入（P1）**

输入框：「我想加一个…」

- 例：“加一个清洗旁通” → 匹配 `clean-bypass` 块。
- 例：“加个蒸汽杆” → 匹配 `steam-wand`。
- 匹配不到时显示 3 个最接近的卡片 + 「去高级模式」。
- 不接模型；用关键词/同义词表，命中率优先，避免“看起来像 AI 但经常错”。

**F2.4 教学提示**

- 每次插入块后显示 1 条 120 字以内的提示：
  - “奶路块包含奶罐、选择阀、奶泵、奶出口；先接奶源，再接出口。”
- 提示可关闭，不重复同一块的提示超过 2 次。
- 「为什么」按钮展开知识库对应条目，不跳转外部文档。

### F3 保存与离开提醒系统（P0，本 PRD 的重点）

**F3.1 三种“保存”必须先定义清楚**

| 概念 | 存在哪里 | 用途 | UI 用词 |
|---|---|---|---|
| 自动保存 | 浏览器 localStorage，5 个版本 | 崩溃恢复、误关恢复 | 「已自动保存在本机」 |
| 保存文件 | 用户选择的 `.json` 路径 | 分享、换电脑、交付、版本管理 | 「已保存到文件」 |
| 导出 | PNG/SVG/JPG/PDF/GIF | 给文档/聊天/打印看 | 「已导出图片」 |

**F3.2 状态栏保存胶囊**

替换现在的 `● 未保存 / ✓ 已保存`：

| 状态 | 显示 | 颜色 |
|---|---|---|
| 刚打开、无修改 | `✓ 已保存到 图纸.json · 14:32` | 绿 |
| 有修改、未存文件 | `● 本机草稿 14:32 · 文件未保存` | 琥珀 |
| 正在写自动保存 | `◌ 正在保存到本机…` | 灰，<800ms |
| 自动保存失败 | `⚠ 本机自动保存失败` | 红，可点重试 |
| 未命名、从未存文件 | `● 未保存到文件 · 本机草稿 14:32` | 琥珀 |
| 只导出过图片 | `● 图片已导出 · 图纸文件未保存` | 琥珀 |

点击胶囊打开「保存说明」Popover：

```text
自动保存（本机）
  每 800ms 防抖保存，保留最近 5 个版本；关掉应用后可恢复。
  不是文件，不能发给别人。

保存文件（JSON）
  生成一个 .json 文件，可分享、换电脑打开、纳入版本管理。
  [保存文件]

导出图片
  PNG/SVG/PDF/GIF，只用于展示，不能再编辑。
```

**F3.3 保存教练（首次编辑）**

触发：本次会话第一次产生实际修改（节点/管路/属性变化），且用户未保存过文件。

形式：右下角卡片，不遮挡画布中心；4 秒后自动收起为状态胶囊，但保留“保存文件”按钮。

```text
修改已自动保存在本机
自动保存用于崩溃恢复；要分享或换电脑，请保存为文件。
[保存文件]  [以后再说]
```

规则：

- 每个浏览器会话最多完整弹出 1 次。
- 点「以后再说」写入 `localStorage`，24 小时内不再弹；状态胶囊持续提示。
- 正在拖动/输入/弹窗时不出现；延迟到 idle 1.5 秒。
- 保存成功后不再弹。

**F3.4 引导动作后的保存提示**

| 触发 | 提示 | 形式 |
|---|---|---|
| 模板插入成功 | “已插入 18 个元件。本机已自动保存；建议保存文件用于分享。” | 右下 Toast 6s，带「保存文件」「继续完善」 |
| 加块成功 | “已插入奶路（4 元件）。本机已自动保存。” | 右下 Toast 4s，带「保存文件」 |
| 一键修复/重编号 | “已重排 12 段管路编号。本机已自动保存。” | Toast 4s |
| 导出图片成功 | “图片已导出。导出图片不等于保存图纸；需要可编辑文件请保存 JSON。” | Toast 5s，带「保存文件」 |
| 连续 10 次编辑或 5 分钟未存文件 | 状态胶囊 pulse 一次 + tooltip | 不弹窗 |

**F3.5 离开提醒**

- **Electron 桌面**：沿用现有自定义关闭弹窗，改为三选一：

```text
保存并退出 / 不保存，直接退出 / 取消
自动备份仍保留最近 5 个版本，可在下次启动时恢复。
```

- **网页**：`beforeunload` 只在“有未保存文件修改”时触发；浏览器原生文案不可定制，所以页面内状态胶囊必须提前表达清楚。
- 演示/验收/故障模式退出不触发保存提示（不是文件修改）。
- 空白画布且无修改：直接关闭，不提示。

**F3.6 保存成功/失败**

- 成功：Toast「已保存到 `xxx.json`」+ 状态胶囊变绿；Electron 提供「在 Finder 中显示」。
- 失败：Toast 红色「保存失败：权限/磁盘/浏览器下载被拦截」+「重试」；不改变 dirty 状态。
- 另存为：保留「另存为…」，成功后更新 `sourceFilePath` 与状态。

**F3.7 防打扰约束**

- 不在画布拖动、文本输入、Modal 打开时弹保存卡。
- 同一会话完整教练最多 1 次；Toast 最多每 2 分钟 1 次。
- 用户点「以后再说」后，24 小时内只保留状态胶囊，不再弹卡。
- 提供设置项「保存提醒：标准 / 仅状态栏 / 关闭」；默认标准。

### F4 教学与首跑引导（P0/P1）

**F4.1 首次打开的三步清单**

空画布底部显示可关闭的清单：

```text
① 选择模板  ② 插入画布  ③ 保存文件
```

完成后逐项打勾；全部完成自动消失；关闭后 7 天内不再出现。

**F4.2 三条 Coach Mark（只教 3 件事）**

1. 空白画布：指向「智能绘图」——“不用从零拖元件，先选一个场景。”
2. 插入后：指向右栏「继续完善」——“这里会告诉你还缺什么。”
3. 第一次修改后：指向保存胶囊——“自动保存在本机；要发给别人，点这里保存文件。”

规则：每条只出现一次；可跳过；不覆盖用户正在操作的位置；深色模式适配。

**F4.3 上下文提示**

- 选中节点时，Inspector 顶部显示“这是什么？[查看原理]”（已有知识库）。
- 待连接端口 hover：“这个口还没接管；点「检查图纸」可定位。”
- 结构检查结果用“问题 + 为什么 + 修复”三行，不只给红色警告。

### F5 视觉与文案（P0）

**F5.1 视觉**

- 生成 Modal：880×620，圆角 16，背景 `var(--panel)`，遮罩 40% 黑；三步指示器在顶部。
- 模板卡：16:9 预览区（浅网格背景）、标题 16px/600、说明 12px/1.5、标签 11px。
- 选中卡：2px 主色边框 + 4% 主色底；hover 抬升 2px。
- 保存胶囊：高 24px、圆角 12、8px 状态点；琥珀/绿/红三态。
- 所有动效 150–200ms；尊重 `prefers-reduced-motion`。
- 深色模式使用现有 CSS 变量，不新增硬编码颜色。

**F5.2 文案**

- 不出现：AI 上下文、指令 JSON、协议、requestId、哈希、Schema、fallback。
- 用词：
  - 「生成图纸」而不是「AI 绘图」
  - 「保存文件」而不是「保存」
  - 「本机草稿」而不是「自动保存」
  - 「待连接」而不是「孤立端口」
- 每句提示只做一件事；标题 ≤14 字，正文 ≤50 字。

### F6 高级模式（本版不投入）

- 现有 `AiDrawingPanel` 协议功能保留，但入口收进「高级：结构化指令」。
- 默认向导不引用 `docs/ai-protocol.md` 的术语；只有高级模式展示。
- 本版不新增模型调用；后续若接 LLM，复用同一套预览/校验/应用/撤销管线。

## 9. 状态与交互规格

### 9.1 向导状态机

```text
closed
 → open.scene        （选场景）
 → open.options      （选配置，可回退）
 → open.preview      （预览，可回退/换模板）
 → inserting         （150ms 过场，不阻塞）
 → inserted          （关闭 Modal，右栏 continue）
 → error             （结构检查失败/插入失败，保留选择）
```

- `Esc` 关闭：已选配置保留到本次会话；不写入图纸。
- 插入失败：不改变原图；Modal 内显示原因 + 重试。
- 非空画布插入：先弹「追加 / 新建」选择；选择后才写入。

### 9.2 保存提醒触发矩阵

| 事件 | 完整教练 | Toast | 状态胶囊 | 关闭弹窗 |
|---|---|---|---|---|
| 首次修改 | 是（会话 1 次） | 否 | 更新 | 否 |
| 模板插入 | 否（若已看过教练） | 是 | 更新 | 否 |
| 加块/修复 | 否 | 是 | 更新 | 否 |
| 导出图片 | 否 | 是（提示不等同保存） | 更新 | 否 |
| 10 次编辑/5 分钟 | 否 | 否 | pulse | 否 |
| 关闭窗口（有未存文件修改） | 否 | 否 | — | 是 |
| 关闭窗口（已存/无修改） | 否 | 否 | — | 否 |

### 9.3 空/非空画布

- 空画布：插入 = 加载；无“追加/新建”选择。
- 非空画布：插入 = 追加到右侧；保持原图；一次撤销。
- 追加时若与现有元件重叠：自动向右偏移 200px，不覆盖。

### 9.4 键盘与无障碍

- Modal 焦点陷阱；`Esc` 关闭；`Tab` 顺序为“上一步 → 下一步 → 关闭”。
- 模板卡支持方向键切换、Enter 选择。
- 保存胶囊 `aria-live="polite"`；错误用 `role="alert"`。
- 颜色不是唯一信息：状态同时用图标 + 文案。

## 10. 技术方案

### 10.1 组件

| 文件 | 作用 |
|---|---|
| `src/smart-draw/templates.ts` | 4 个模板元数据：id/title/desc/keywords/options/build |
| `src/smart-draw/build.ts` | 用 `createNode`/`createPipe` 生成节点/管路；固定网格布局；输出 `nodes/pipes` |
| `src/smart-draw/intents.ts` | 关键词 → 块/模板的映射（同义词表） |
| `src/components/SmartDrawingWizard.tsx` | 三步 Modal |
| `src/components/SmartDrawingPanel.tsx` | 插入后的「继续完善」右栏 |
| `src/components/TemplateCard.tsx` | 模板卡 + 预览 |
| `src/components/DiagramPreview.tsx` | 从 `AiDrawingPanel` 抽出的共享 SVG 预览 |
| `src/components/SaveStatusPill.tsx` | 状态栏保存胶囊 + Popover |
| `src/components/SaveCoach.tsx` | 首次编辑保存教练卡 |
| `src/components/SaveDialog.tsx` | 关闭三选一弹窗（可复用现有 close-save-card） |

### 10.2 Store 改动

- `insertSmartDrawing(result, mode: "replace" | "append")`：
  - `replace`：仅空画布；加载新图。
  - `append`：保留原图，节点/管路追加到右侧；一次 `updateDiagram`，一次撤销；选中新增；`fitToScreen`。
- `appendSmartBlock(block, anchorPortId?)`：
  - 有 anchor：自动连接；无 anchor：放置并标记待连接。
- `UIState` 增加：
  - `lastAutosaveAt?: number`
  - `fileSavedAt?: number`
  - `saveNudge?: { kind: "first-edit" | "milestone"; at: number } | null`
- 自动保存模块在 `persistAutosave` 成功后 `notifyUI({ lastAutosaveAt: Date.now() })`；不改 `dirty`。
- `dirty` 语义保持“文件未保存”；状态胶囊同时读 `dirty` + `lastAutosaveAt` + `sourceFilePath`。

### 10.3 保存文件

- 复用现有 `saveJSONFile` / Electron `saveJsonDialog` / `markSaved`。
- 成功后 `markSaved()` + `setSourceFilePath(path)` + `recordSavedAt(diagram.id)`；失败不动 `dirty`。
- 导出图片不调用 `markSaved`。

### 10.4 结构检查

- 生成后调用 `collectAdvice`（structure category）。
- 预览页显示 error/warning 数；插入前允许“仍然插入”，但必须提示。
- 一键修复复用 `applyFix`（`renumberPipes` 已存在）。

### 10.5 i18n 与测试

- 所有新文案中英双语；英文模式无中文残留测试。
- 测试：
  - 每个模板的节点/管路数、端口合法、无孤立元件；
  - 向导 3 步、回退、空/非空插入、撤销；
  - 保存胶囊 5 种状态；
  - 教练卡只出现一次、`以后再说` 24h 生效；
  - 关闭弹窗三选一；
  - 英文模式无中文。
- 性能：模板生成 <50ms；预览渲染 <100ms；不新增运行时依赖。

## 14. 风险与开放问题

### 风险

1. **模板布局不匹配真实机型**：用户可能觉得“生成得不像”。对策：文案始终说“起步草图”；模板卡标元件数；允许手动改；不承诺 1:1。
2. **接点选择复杂**：新手可能不知道接哪里。对策：只高亮 2–4 个兼容接点，用中文标签；提供“先放右边”兜底。
3. **保存提示变骚扰**：对策：完整教练每会话 1 次；24h 免打扰；状态胶囊常驻；设置可调。
4. **“智能”预期过高**：不叫 AI，避免用户以为能任意生成；副标题明确“模板 + 引导”。
5. **模板/块维护成本**：先 4 模板 + 4 块，不做无限扩展；每加一个必须有测试和预览。

### 需要拍板

1. 生成阶段用 **Modal**（推荐）还是右栏？推荐 Modal，完善阶段用右栏。
2. 非空画布默认 **追加** 还是 **新建**？推荐让用户选，默认追加。
3. 保存教练默认 **标准** 还是 **仅状态栏**？推荐标准，可在设置改。
4. 模板首批是否只做咖啡机？推荐是；通用液压会拉大术语和模板范围。
5. 是否保留「高级：结构化指令」入口？推荐保留但收起，本版不推广。

## 15. 一句话总结

把「AI 绘图」变成「智能绘图」：新手先选场景拿到一张可编辑的起步图，生成后按“还缺什么”继续加块；每一次修改都明确告诉他“已自动保存在本机、还没保存成文件、离开会怎样”。先做到不迷路、不丢图，再谈 AI。
