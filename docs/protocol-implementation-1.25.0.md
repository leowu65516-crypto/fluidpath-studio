# FluidPath Studio 1.25.0：协议第一阶段交付与验收

日期：2026-09-18。依据：FluidPath 图纸规范与 AI 绘图协议 v0.2。

## 本轮已交付

### 故障代码与关联回路

工具栏「故障代码」支持自定义代码、中英文名称、排查说明、选中元件/管路的替换、追加与移除绑定，以及多代码叠加高亮。高亮可定位、临时显示隐藏对象、设置颜色与缓慢呼吸。

定义存入图纸 `settings.diagnosticProfile`，随 JSON 和机型包保存。单独导入代码库时清空原图目标引用，要求重新绑定，避免不同机型使用相同旧 ID 时误绑。已经删除的关联对象会明确提示。

数值规则支持单位、阈值、连续保持时间、检测前提、宽限期、恢复阈值和恢复保持时间、锁存、确认与复位。简单规则用表单配置；组合条件用高级 JSON 配置。手动输入属于教学虚拟信号，未连接实际传感器。模拟时间、样本、报警与事件保存在独立会话，不写入工程泵阀状态。

数值输入在按 Enter 或离开输入框后提交，避免小数输入的中间状态被采样。缺失、过期或无效数据不会被当成健康读数；连续条件会被打断，已存在的活动报警仍保留。确认报警与恢复/复位是独立行为。

支持代码库 JSON、故障 Markdown 报告导出，以及导出图像时显式选择是否包含诊断高亮。报告中的关联范围不代表已确定根因。

### AI 绘图接入基础

工具栏「AI 绘图」提供「下载 AI 上下文 → 粘贴 JSON → 校验并预览 → 应用全部变更」。示例可直接演示完整流程。

当前白名单：新增元件、连接端口、修改标签、设置泵阀状态、定义故障码关联。校验包括元件词典、端口存在性/占用/方向、介质枚举、布局、操作字段、请求数量和大小限制。当前词典支持 25 种元件。

应用前再次校验图纸 SHA-256；图纸已经变化或请求已经执行时拒绝应用。全部操作成功才一次写入，可一次撤销；不执行任意代码、不接受任意属性，也不允许 AI 借教学强制流动获得工程 PASS。

本入口尚未连接模型服务。当前为 `fluidpath.ai-operations` / `0.2-draft` 的受限实现，目标是现有图纸 Schema 3 和 `fluidpath-legacy-catalog/1`，不是完整 Schema 4 实现。

### 验收与导入正确性

验收结果增加 PASS、FAIL、INVALID。空断言、互相冲突的断言、无效状态引用和缺失管段均不能通过。缺失管段的实际状态为 `missing`，不能伪造为“停流”。无头 CLI 无案例时输出 NOT_RUN 并返回非零退出码。

导入先迁移旧版嵌套坐标，再校验图纸结构；不支持的未来版本明确拒绝。带诊断配置的图纸在进入 store 前检查诊断字段与规则。验收副本运行后恢复引擎缓存指向原图纸。

## 本轮边界与后续模块

本轮没有重写液路仿真引擎。完整双向压差判流、动态混合介质、锅炉存水/温度/压力独立状态、可配置泵工艺前提、完整 v4 Schema 迁移、真实传感器/回放接入及模型服务仍需后续实现。不能据本轮的通过项宣称所有新 JSON 的全部物理工况已经系统性解决。

尤其是“停泵不等于锅炉无水无温”和“无单向阀的回路可能双向通流”仍是下一阶段引擎建模要求，本轮诊断高亮不会改变它们，也不会用强制动画掩盖它们。
